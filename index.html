持参薬チェック

概要

PTP シートには渕にロット番号のみ印字され、使用期限は外箱にしかないことが多い。 各社の使用期限検索サイトを個別に開く手間という実務課題を解消するため、 42 社の使用期限検索ページ（ほかに問い合わせ窓口のみの 7 社）を 1 画面に集約し、ロット番号を貼り付けるだけで即検索できるツールを開発。 薬品名を入れると、どのメーカーの薬かも調べられる。 錠剤鑑別・報告書 PDF 印刷も統合し、独自ドメイン jisanyaku-check.com で公開中。

操作デモ

主な機能

🔍42 社の製薬会社 使用期限検索ページへワンタップアクセス
🏷️薬品名からメーカーを判定（10,576 品目）
💊錠剤鑑別（PMDA・ハイパー薬事典へのワンタップ検索）
⭐よく使うメーカーのお気に入り登録・並び替え
📋ロット番号コピー機能（各社サイトにそのまま貼り付け）

開発の背景・工夫した点

① PTP シートの使用期限問題という「実務で感じた課題」をそのままプロダクト化
② 製薬会社の公開 API が存在しないため、スクレイピングではなくリンク集方式を採用し持続可能な運用を実現
③ ロット番号をクリップボードにコピーして各社サイトで即検索できる UX を設計

おくすりヒーロー

薬局実習で直面した「子どもが薬を飲んでくれない」課題を、ゲーム体験に変える 3〜6 歳向け服薬支援アプリ

概要

薬局実習中、処方どおりに飲めず残薬を持ち帰る小児が多いことを実感した。 苦味や剤形の問題に加え、「飲むこと自体が嫌な体験」になっている点が本質的な課題と考え、 服薬をヒーローの物語とごほうびに置き換える iOS アプリを開発。 服薬記録・保護者向けの飲み合わせ情報・服薬指導のヒントも統合し、 子ども側の動機づけと保護者側の判断材料を 1 つのアプリで扱う設計とした。 2026 年 10 月には同じコードからブラウザ版を書き出して公開し、手描き調の画面・効果音・ カメラで口の位置を認識する演出を加えた。

操作デモ

主な機能

🦸バディ育成（6 種 × 5 進化段階）— 服薬でレベルアップし仲間が増える
⚔️体内スライドショー演出 — 口→食道→胃→腸をたどりバイキンを倒す（時間制限なし・必ず勝てる設計）
🎟️デジタルシール帳 — 478 枚のシールを台紙に自由にドラッグして貼る
📖シリーズ図鑑 — 40 シリーズ単位で収集し、達成感が続く設計
📷カメラ演出 — ヒーローが薬を口まで運ぶ（既定オフ・録画も送信もしない）
🧑‍🎨自作ヒーロー — 好きな写真から自分だけのバディを作成（端末内のみ保存）
💊薬価基準 7,020 品目からの予測変換・用法/剤形による自動グルーピング
🥄粉薬と服用補助食品の飲み合わせ 81 剤 × 21 食品を保護者向けに表示

技術スタック

React Native / Expo SDK 54 TypeScript（strict） AsyncStorage PanResponder / Animated expo-camera / notifications Node.js（画像・データ処理）

アーキテクチャ

サーバーを持たない完全ローカル構成。服薬記録・シールの配置・自作ヒーローの写真は すべて端末内に保存し、外部送信を行わない。 画像アセットとマスタデータは Node.js スクリプトで生成し、 「実体（画像ファイル）を唯一の情報源」として コード側の登録表を自動生成することで、登録漏れ・不整合を構造的に排除している。

開発の背景・工夫した点

① 実習で見た「飲めずに残る」課題を起点に、子どもが負ける体験を作らないゲーム設計（時間制限なし・必ず勝てるミニゲーム）
② 収集要素は 478 種を一列に並べずシリーズ単位に分割。全種収集は 4.4 年かかる計算になるため、数週間で 1 シリーズが埋まる構造に変更
③ 素材 1,997 枚を機械的に分類するため、「同じ前置きの後に 3 種類以上の語尾が続く位置」を切れ目とみなすアルゴリズムを実装し、動物名の登録漏れによる分類崩れを解消
④ 飲み合わせ表は PDF から ToUnicode CMap を解析して抽出。フォントごとに CMap を分離しなかった初期実装の誤りを、記号総数の検算（1,158→1,700）で発見し全 81 剤を復元
⑤ 薬剤データは商品名・一般名の双方で照合。異性体表記・塩・剤形の表記ゆれを正規化し、薬価基準の粉薬 2,051 品目中 185 品目をカバー
⑥ 実機に依存しないロジック検証スクリプト（81 項目）とデータ整合性チェッカーを整備し、UI を起動せず回帰を検出
素材について：飲み合わせ表・イラスト素材はいずれも第三者の著作物であり、 各利用規約を確認のうえ出典を表記して使用している。

CTCAE グレード判定

病院実習で抗がん剤の副作用評価に時間がかかった経験から作った、CTCAE v5.0 の検索・判定ツール

概要

病院実習で、抗がん剤治療中の患者の副作用を CTCAE で評価する際、PDF から該当項目とグレードを探す作業に時間がかかった。 CTCAE v5.0（JCOG 日本語訳）の全 837 項目を日本語で検索し、Grade を確認・記録できるツールとして作成。 検査値から判定できる項目は、JCCLS 共用基準範囲を既定値に使って自動で Grade を出す。

主な機能

🔍全 837 項目を SOC・Term の日本語で検索
🧪検査値を入れると自動で Grade 判定（23 項目）
📝数値で決まらない項目は、原文の Grade 文言から選ぶ方式
💉レジメン・薬剤名から関連する有害事象を引ける
🗂️判定結果を記録用にまとめて出力
🔒完全ローカル処理・外部送信なし

技術スタック

HTML / CSS / JavaScript（単一ファイル） Node.js（データ生成・テスト） GitHub Pages・独自ドメイン

開発の背景・工夫した点

① 基準の文言は JCOG 版の PDF から抽出し、原文と照合してから登録
② 体表面積の割合や ADL の制限など数式にできない基準は、架空の数値ロジックを作らず原文の選択肢から選ぶ方式に
③ 基準範囲は既定値入りで、測定値を入れるだけで判定できる
④ 患者のデータを扱うため、通信を一切行わない設計

PISCS AUC 変化予測

CR-IR 法で薬物相互作用による AUC の上昇を計算する、薬学生・薬剤師向けの学習用ツール

概要

基質薬と阻害薬（または誘導薬）を選ぶだけで、CR-IR 法（AUCR = 1 / (1 − CR × IR)）・CR-IC 法により AUC の変化比を計算する。 CYP3A・CYP2D6・CYP2C9・CYP2C19 に対応し、計算の過程と出典をあわせて表示する。

主な機能

🧮阻害（IR）・誘導（IC）の両方を計算
📊複数の相手薬を表と棒グラフで比較
🧬酵素別チェック・PISCS 分類（CYP3A）
✍️他の資料の CR・IR を手入力しても計算
🔤一般名・商品名・ひらがなで部分一致検索
🕘計算履歴の保存と CSV 出力（患者情報は保存しない）

技術スタック

HTML / JavaScript（単一ファイル） Node.js（データ生成・テスト） CSV（薬剤データ）

工夫した点

① 資料の間で値が食い違う薬は、原本で確かめてから採用
② 複数の酵素の結果は掛け合わせない（各酵素の寄与が独立だとは確認できないため）
③ 「推定」「分類」「注意喚起」「臨床判断」を区別して表示し、計算結果を処方の判断に使わないよう明記

後付け IoT お薬カレンダー

市販のお薬カレンダーに後付けして、服薬の状況を薬剤師に届ける服薬フォロー支援

概要

患者が使い慣れた市販のお薬カレンダーをそのまま使い、後付けの装置で服薬の状況を記録して、飲み忘れが続く患者を薬剤師が把握できるようにする。 771 試験のメタアナリシスで、コンピュータからの通知よりも薬剤師による対面の介入のほうが効果が大きかったことを根拠に、 患者への通知を増やすのではなく、薬剤師の声かけにつなげる設計とした。

主な機能（構想）

📦メーカーを問わず市販のカレンダーに後付け
🧑‍⚕️飲み忘れが続く患者を薬剤師が把握
💬連絡は LINE（専用アプリを入れなくてよい）
🔬試作機で、実物の PTP シートの取り出しを検出できることを確認

技術スタック

TypeScript / Next.js マイコン（ESP32） LINE 通知
